# 完善你的产品方案

有个想做的东西但不知从何下手？这个 skill 扮演产品经理，帮你把应用、个人工具、自动化、功能原型或游戏想法梳理成可开发、可阶段验收的 `SPEC.md` 实现说明书。从“我想做个 XX”开始，一起问清楚谁会用、什么时候用、第一版先跑通什么，再写成可以直接交给开发的方案。

## 这些时候可以找它

- **脑子里有画面，还说不清需求**：“我想做个整理收藏的工具，帮我完善这个产品方案。”从一次实际使用讲起，理清怎么收、怎么找、什么时候算整理好了。
- **想用 AI coding 做自己的小工具**：“帮我把每周整理账单的自动化梳理成 SPEC.md。”把输入、处理步骤和要交付的结果写清楚，让 coding agent 有东西可照着做。
- **功能越想越多，第一版迟迟开不了工**：“这些功能帮我排一排，先做一个我能用起来的版本。”确定核心路径，把后续想法放进阶段规划。
- **准备做原型或游戏**：“我想做个解谜小游戏，先帮我梳理首版玩法和验收场景。”讲清楚玩家怎么开始、怎么推进、怎样算这一版做完。
- **已有方案，想交给开发**：“帮我检查这份方案，把含糊的地方问清楚，补成 SPEC.md。”把需要开发临场猜的地方提前说透。

## 它会产出什么

- 项目一句话定义
- 目标用户和使用场景
- 核心路径
- Phase 1 最小可运行范围
- 后续阶段建议
- 明确不做的内容
- 容易失控的范围风险
- 假设和开放问题
- 场景验收测试
- 开发交接提示
